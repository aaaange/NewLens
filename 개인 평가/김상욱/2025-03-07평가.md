## 1. 개인 빅데이터 개념 공부
### CAP 이론

Consistency(일관성) / Availability(가용성) / Partition Tolerance(파티션 허용성)

분산 시스템 환경에서 3가지가 동시에 만족될 수 없다.

#### Consistency(일관성)

- 데이터를 저장하거나 업데이트 시, 모든 노드가 같은 시점에서 동일한 데이터를 볼 수 있어야 한다. 즉, 모든 노드가 같은 데이터를 가지고 있어야 한다.

#### Availability(가용성)

- 시스템의 일부 노드나 네트워크에 문제가 생겨도 정상 동작이 가능해야 하며 사용자 요청에 대한 응답을 항상 제공할 수 있어야 한다.
- 클라이언트의 대응이 핵심

#### Partition Tolerance(파티션 허용성)

- 분산 시스템에서 노드간 네트워크 단절이나 지연이 발생하더라도 시스템이 동작을 계속 유지할 수 있어야 한다.
- 즉, 시스템의 완전 정지가 되지 않는 것이 핵심

### 분산 시스템의 특성

Failover(장애 극복), Scalability(확장성), Replication(복제)

---

### Failover(장애 극복)

#### 개념

- Failover란 시스템에서 특정 노드나 프로세스가 장애를 일으켜 더 이상 정상적으로 작동안하는 경우, 자동으로 백업 노드나 대기 중인 서버로 작업을 넘겨서 서비스를 중단 없이 계속 수행하도록 하는 메커니즘.
- 서버, 네트워크, 스토리지 등 다양한 계층에서 장애가 발생했을 때 빠르게 감지하고 교체하는 과정.

#### 특징 및 구현 방법

1. **장애 감지(Health Check)**
    - 정기적으로 서버나 서비스의 상태 모니터링하여 파악.
    - Hearbeat(하트비트) 방식으로 노드 간 Ping/Pong을 교환하거나, API 엔드포인트를 주기적으로 호출하여 정상 응답을 확인합니다.
2. **자동 전환(Automatic Failover)**
    - 장애가 감지되면 미리 준비된 대체 서버(Standby Node)나 다른 가용 노드로 트래픽을 자동 전환(Failover)
    - DNS 라우팅 정책 변경, 로드 밸런서의 Target 변경, 리더 선출 알고리즘 등을 통해 전환
3. **무중단 서비스(High Availability)**
    - Failover가 빠르게 일어나면 서비스 중단 시간을 최소화하거나 없앨 수 있습니다.
    - 장애 발생 시에도 사용자 입장에서는 서비스를 계속 사용할 수 있으므로 높은 가용성이 보장

#### 장점

- 신뢰성(Reliability) : 장애 발생 시 즉시 대응하여 신뢰도 향상
- 가용성(Availability)

#### 단점

- 비용 증가 : 백업 노드나 스탠바이 환경을 유지해야 하므로 추가 비용이 발생
- 복잡성 증가 : 장애 탐지, 노드 전환 로직, 데이터 동기화 로직 등 구현이 복잡.

---

### Scalability(확장성)

#### 개념

- 시스템에 부하(트래픽, 데이터)가 증가할 때, 시스템 성능을 유지하거나 더 높은 성능을 내기 위해 자원을 효율적으로 확장할 수 있는 능력
- 수직 확장(Vertical Scaling)과 수평 확장(Horizontal Scaling)

#### 수직 확장(Vertical Scaling)

- 물리적으로 성능 높임

#### 수평 확장(Horizontal Scaling)

- 서버의 개수를 늘려 분산 처리를 통해 성능 향상
- 클라우드 환경에서는 일반적으로 수평 확장을 선호하며, 부하에 따라 노드를 자동으로 늘리거나 줄이는 오토 스케일링(Auto Scaling) 기능 제공.

#### 장점

- 유연성 : 필요에 따라 자원을 자유롭게 늘리거나 줄일 수 있으므로 비용 효율적
- 고성능 : 트래픽이나 데이터 양이 급격하게 증가해도 유연하게 대응 가능

#### 단전 및 고려 사항

- 데이터 분산 처리의 복잡성 : 여러 노드에서 데이터를 분산 저장 및 처리할 경우, 일관성을 유지하기 위한 추가 로직 필요
- 네트워크 오버헤드 : 노드 간 통신이 증가하면 네트워크 지연이나 오버헤드가 발생할 수 있습니다.

---

### Replication(복제)

#### 개념

- Replication이란 데이터를 여러 노드에 중복 저장하여 가용성, 내결함성(Fault Tolerance), 성능 등을 향상시키는 기법.
- 분산 데이터베이스나 분산 파일 시스템에서 자주 사용되며, 노드 데이터를 복제함으로써 한 노드에 장애가 발생하더라도 다른 노드에서 데이터를 제공할 수 있습니다.

#### 복제 전략(Replication Strategy)

1. **동기적 복제(Synchronous Replication)**
    - 데이터 변경이 발생하면 모든 복제본에 해당 변경이 반영된 후에 작업을 완료로 처리
    - 장점 : 데이터 일관
